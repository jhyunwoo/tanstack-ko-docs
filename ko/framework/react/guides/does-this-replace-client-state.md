title: TanStack Query는 Redux, MobX 또는 기타 전역 상태 관리자를 대체합니까?
---




몇 가지 중요한 항목부터 시작해 보겠습니다.

- TanStack Query는 서버와 클라이언트 간의 비동기 작업을 관리하는 **서버 상태** 라이브러리입니다.
- Redux, MobX, Zustand 등은 비록 TanStack Query와 같은 도구와 비교할 때 비효율적이지만_ 비동기 데이터를 저장하는 데 사용할 수 있는 **클라이언트 상태** 라이브러리입니다.

이러한 점을 염두에 두고 간단히 대답하자면 TanStack Query는 **클라이언트 상태에서 캐시 데이터를 관리하는 데 사용되는 상용구 코드 및 관련 배선을 대체하고 단 몇 줄의 코드로 대체한다는 것입니다.**

대부분의 애플리케이션의 경우 모든 비동기 코드를 TanStack Query로 마이그레이션한 후 남겨지는 실제로 **전역적으로 액세스 가능한 클라이언트 상태**는 일반적으로 매우 작습니다.

> 응용 프로그램이 실제로 엄청난 양의 동기식 클라이언트 전용 상태(비주얼 디자이너 또는 음악 제작 응용 프로그램 등)를 가질 수 있는 상황이 여전히 있습니다. 이 경우에도 여전히 클라이언트 상태 관리자가 필요할 것입니다. 이 상황에서는 **TanStack Query가 로컬/클라이언트 상태 관리를 대체하지 않는다는 점에 유의하는 것이 중요합니다**. 그러나 문제 없이 대부분의 클라이언트 상태 관리자와 함께 TanStack Query를 사용할 수 있습니다.

## 인위적인 예

여기에 전역 상태 라이브러리에 의해 관리되는 "전역" 상태가 있습니다.

```tsx
const globalState = {
  projects,
  teams,
  tasks,
  users,
  themeMode,
  sidebarStatus,
}
```
현재 전역 상태 관리자는 `projects`, `teams`, `tasks` 및 `users`의 4가지 유형의 서버 상태를 캐싱하고 있습니다. 이러한 서버 상태 자산을 TanStack Query로 이동한다면 나머지 전역 상태는 다음과 같습니다.

```tsx
const globalState = {
  themeMode,
  sidebarStatus,
}
```
이는 또한 `useQuery` 및 `useMutation`에 대한 몇 가지 후크 호출을 통해 서버 상태를 관리하는 데 사용된 상용구 코드를 제거할 수도 있음을 의미합니다.

- 커넥터
- 액션 크리에이터
- 미들웨어
- 감속기
- 로딩/오류/결과 상태
- 컨텍스트

이러한 모든 항목을 제거한 후 **"이 작은 전역 상태에 대해 클라이언트 상태 관리자를 계속 사용하는 것이 가치가 있는가?"**라고 자문할 수 있습니다.

**그것은 당신에게 달려 있습니다!**

하지만 TanStack Query의 역할은 분명합니다. 이는 애플리케이션에서 비동기 배선과 상용구를 제거하고 단 몇 줄의 코드로 대체합니다.
